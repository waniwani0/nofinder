# ノーファインダー — 実機で動かす

## 1. サーバーを起動（Mac 側）

```
python3 serve.py
```

自己署名の証明書を作って、このフォルダを HTTPS で配信します。
`https://<MacのIP>:8443/` が表示されます。

> カメラ（getUserMedia）はセキュアコンテキストでしか動きません。
> `http://` の直打ちでは起動しないので、HTTPS で配る必要があります。
> ポートが埋まっていると言われたら `lsof -ti :8443 | xargs kill`。

## 2. スマホで開く

Safari で、表示された URL のどれかを開きます。起動時に届きうるアドレスを全部並べます。

**つなぎ方は 3 通り。どれでも構いません。**

| つなぎ方 | Mac 側のアドレス | 備考 |
| --- | --- | --- |
| iPhone にテザリング（IPv6 の回線） | `240b:...` などの **IPv6** | いまはこれ。下の注意を参照 |
| iPhone にテザリング（IPv4 の回線） | `172.20.10.x` | |
| 同じ Wi-Fi / LAN | `192.168.x.x` など | 職場や公共の Wi-Fi は端末間の通信が遮断されていることがあります |

### 注意: `192.0.0.2` は使えません

IPv6 オンリーの回線に iPhone 経由でつなぐと、macOS の IPv4 アドレスは `192.0.0.2/32` になります。
これは **464XLAT (CLAT) の変換用アドレス**で、Mac の内部だけのものです。
他の端末からは到達できないので、ここへ繋ごうとすると「インターネットに接続されていない」と言われます。

この場合に使うのは **IPv6 アドレス**です。URL では角括弧で囲みます:

```
https://[240b:c020:402:f9fd:1489:eec4:f05a:4479]:8443/
```

`serve.py` は IPv4 と IPv6 の両方で待ち受け、届かないアドレス（`192.0.0.x`、リンクローカル、
入れ替わる IPv6 の一時アドレス）を除いた候補だけを表示します。

1. 「この接続はプライベートではありません」→ **詳細を表示** → **このWebサイトを閲覧**
2. カメラの許可を **許可**

## 3. ホーム画面に追加

共有ボタン → **ホーム画面に追加**。
アドレスバーのない全画面のアプリとして起動し、横向きで開きます。

一度開けば Service Worker がキャッシュするので、**Mac のサーバーを止めてもアプリは動きます**。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（`build.py` が生成） |
| `manifest.webmanifest` | アプリ名・アイコン・横向き固定 |
| `sw.js` | オフライン用キャッシュ |
| `serve.py` | HTTPS 配信サーバー |
| `build.py` | `../nofinder.html` から `index.html` を生成 |
| `make_icons.py` | アイコン画像を生成 |

アプリを直すときは `../nofinder.html` を編集して `python3 build.py` を走らせてください。

## 撮った写真

端末のブラウザ内（IndexedDB）に保存されます。写真アプリには自動で入りません。
残したい 1 枚は、裏ぶた（現像画面）で拡大して長押し →「"写真"に追加」。

## 回線が IPv6 オンリー（4G / 5G）の場合

USB テザリングのままだと、スマホから Mac には**届きません**。

- **IPv4**: iOS はテザリング時、自分に `192.0.0.1`、Mac に `192.0.0.2/32` を割り当てます。
  ただしスマホ自身に IPv4 の接続がないので、iOS は IPv4 リテラル宛のアクセスを
  接続する前に蹴ります（「iPhone がインターネットに接続されていないため…」）。
- **IPv6**: Mac とスマホは同じ `/64` を共有しますが、スマホはその宛先を
  セルラー側へ送ってしまい、ケーブルの先には戻りません。

**直し方**: iPhone の「インターネット共有」を **Wi-Fi** でオンにして、Mac をその Wi-Fi に接続します。
外部の Wi-Fi は不要です。Mac が `172.20.10.x`、iPhone が `172.20.10.1` という
本物の IPv4 サブネットに乗るので、お互い普通に届きます。
`serve.py` を起動し直すと正しい URL が出ます。

`serve.py` はこの行き止まりを検出して、起動時に警告を出します。

## うまくいかないとき

**「iPhone がインターネットに接続されていないため…」と出る**

`192.0.0.2` に繋ごうとしています。上の「`192.0.0.2` は使えません」を読んで、IPv6 の URL を使ってください。

**「"HTTPS-Only" が有効になっている HTTP URL に対するリクエスト」と出る**

URL が短すぎます。`192.0.0.2` だけ入れるとブラウザは `http://192.0.0.2`（80番）へ行きますが、
サーバーは **8443番の HTTPS** です。80番には何もありません。

```
https://192.0.0.2:8443/
```

`https://` と `:8443` を両方入れてください。ポートを省きたい場合は 443 で起動します（要 sudo）:

```
sudo python3 serve.py --port 443
```

これなら `192.0.0.2` と打つだけで届きます。HTTPS-Only モードが自動で https に上げてくれます。

**Firefox / Chrome で開いている**

Safari を使ってください。iOS でホーム画面にアプリとして追加できるのは Safari だけです。

**証明書の警告の先に進めない**

「詳細を表示」→ ページ下部の「このWebサイトを閲覧」→「訪問」。
自己署名証明書なので警告は必ず出ますが、進めば正規のセキュアコンテキストとして扱われ、カメラが使えます。

**「ポートはすでに使われています」**

```
lsof -ti :8443 | xargs kill
```
